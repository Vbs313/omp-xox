# Explain

Explain $@ at the right level of detail.

## High-Level Summary

- What does this code do? State the purpose in one or two sentences.
- Where does it fit in the larger system? What calls it and what does it call?
- What problem does it solve and why was this approach chosen?

## Structure Walkthrough

- Describe the major components or sections.
- For each component: what it does, what data flows through it, and what it produces.
- Call out any non-obvious patterns, algorithms, or design decisions.

## Key Details

- How does error handling work? What can fail and what happens then?
- What are the assumptions the code makes about its inputs and environment?
- Are there performance characteristics worth noting? Time or space complexity.

## Invariants & Gotchas

- What must always be true for this code to work correctly?
- Any subtle interactions with other parts of the system?
- What would a maintainer need to know before modifying this code?

Use concrete examples and refer to specific line numbers where helpful.
